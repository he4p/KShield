01 - Introduction

The Linux Security Crisis

03 / 10
Recent High-Impact CVEs
CVE-2026-31431 - "Copy Fail"  ·  May 2026
Universal local privilege escalation
Logic flaw in the kernel crypto API. A 732-byte Python script roots Ubuntu, RHEL, and Amazon Linux - every major distro since 2017.
CVE-2026-46333 - "Fragnesia"
allows unprivileged users to read sensitive root files
The flaw was disclosed by Qualys and patched by Linus Torvalds on May 14, 2026.
CVE-2026-43284 - "dirty frag"
xfrm-ESP Page-Cache Write
Can obtain root privileges on major Linux distributions by chaining the xfrm-ESP Page-Cache Write (CVE-2026-43284) vulnerability and the RxRPC Page-Cache Write (CVE-2026-43500) vulnerability.
Why Traditional Defenses Fail
User-space blind spot
Antivirus and EDR run above the kernel. They cannot see or stop attacks that live inside it.
Rootkits are invisible by design
A kernel attacker controls the very API your security tools call - they can forge clean answers.
Patch cycles too slow
Enterprise patch windows of 30–60 days leave systems exposed while exploit code is already public.
A recurring attack pattern
Gain any foothold → exploit a kernel bug → own the machine. This chain repeats across every major 2024–2025 incident.

What is Kernel Security?

04 / 10
The Linux kernel is the core of the OS. It manages every process, file, and hardware interaction. Whoever controls the kernel, controls everything.

Unrestricted hardware access · no restrictions
🎯
Ring 1 - Drivers
Device drivers & kernel modules
Ring 1
Ring 2 - System libs
glibc, system calls interface
Ring 2
Ring 3 - User applications
Your code runs here - most restricted
Ring 3
Why attackers target Ring 0
⚔️
Total system control
A kernel attacker can read any memory, intercept any call, hide any process, and disable any security tool.
👁️
Stealth by design
Rootkits hook kernel functions to forge fake outputs. Your ls, ps, and netstat all lie to you.
🔑
Persistence
Kernel implants survive reboots via bootkits and reinstall themselves if user-space defenses remove them.
🚀
Defense must also live in Ring 0
You cannot monitor the kernel from user space. Effective defense requires kernel-level visibility - exactly what eBPF provides.
03 - Technology

What is eBPF?

05 / 10
eBPF lets you run sandboxed programs inside the Linux kernel - without writing kernel modules or rebooting. It's the foundation of modern Linux security tools.
How it works
1
Write - Author an eBPF program in restricted C (or use libbpf / Go)
2
Verify - The kernel's verifier statically proves the program is safe: no infinite loops, no null dereferences
3
JIT compile - Translates to native machine code for near-zero overhead
4
Hook - Attach to kernel events; data flows back via ring buffers and BPF maps
Attachment Points Ataree Uses
kprobes
Dynamic hooks on any kernel function - fully flexible
Tracepoints
Stable static probe points - syscalls, scheduler events
LSM hooks
Security policy enforcement - can block operations
Ring buffers
Lock-free, high-throughput event streaming to user space
Why eBPF over kernel modules?
✓  Kernel-verified safe - no crashes
✓  No recompile, no reboot required
✓  Portable across kernel versions via CO-RE / BTF
✓  <1% CPU overhead in production
